# 映画館の座席予約システム

## プロジェクトの背景

「ひろこむシネマ」は、5つのホールを持つ映画館です。受付のスタッフは、上映予定の確認、空席の確認、座席の予約、予約のキャンセルを行うために、このコンソールアプリケーションを使っています。

あなたは、このシステムの保守担当になりました。既存のプログラムを読み、動作を調査し、不具合を修正してください。その後、受付で利用する上映回ごとの集計機能を追加します。

プログラムと基本的なテストは用意されています。配布時のテストはすべて成功しますが、仕様のすべてを確認しているわけではありません。実際の操作と仕様を比較し、自分で不具合を見つけてください。

## 準備と実行

IDEでも作成した `.venv` を選びます。有効化後、次のコマンドを実行します。
```bash
python -m pip install -r requirements.txt
python main.py
```

テストの実行:
```bash
python -m pytest -q
```

予約・キャンセルを行うと `bookings.json` が更新されます。操作前にこのファイルのコピーを作成しておくと、同じ条件で再現できます。元に戻す場合はプログラムを終了してからコピーを戻してください。ほかの3つのJSONは読み取り専用のマスターデータです。

## ファイルと読む順序

| 順序 | ファイル | 内容 |
| --- | --- | --- |
| 1 | `main.py` | 起動、メニュー、入力、表示、保存の呼び出し |
| 2 | `movie.py` | 映画の情報 |
| 3 | `hall.py` | ホールの情報と座席番号の範囲 |
| 4 | `screening.py` | いつ、どの映画を、どのホールで上映するか |
| 5 | `booking.py` | 1席分の予約とキャンセル状態 |
| 6 | `cinema.py` | オブジェクトの検索、空席確認、予約・キャンセル |
| 7 | `cinema_storage.py` | JSONの読み込みと予約の保存 |
| 8 | `test_cinema.py` | 既存の動作を確認するテスト |
| 9 | `bug_report.md` | 調査と修正の記録 |

## データの構造

JSONをファイルのデータベースとして利用します。SQLiteなどのデータベース管理システムは使用しません。

| ファイル | 配布時の件数 | 主な項目 |
| --- | --- | --- |
| `movies.json` | 8件 | `movie_id`, `title`, `release_year`, `duration_minutes` |
| `halls.json` | 5件 | `hall_id`, `name`, `seat_count` |
| `screenings.json` | 30件 | `screening_id`, `movie_id`, `hall_id`, `starts_at`, `price` |
| `bookings.json` | 50件 | `booking_id`, `screening_id`, `customer_name`, `seat_number`, `status` |

映画 → 上映回 → 予約、ホール → 上映回、という関係です。例えば、予約の `screening_id` で上映回を探し、その上映回の `movie_id` と `hall_id` で映画とホールを取得できます。JSONにはオブジェクトそのものを入れず、IDを保存します。

| ホール | 座席数 |
| --- | ---: |
| 第1ホール | 80 |
| 第2ホール | 60 |
| 第3ホール | 40 |
| 第4ホール | 30 |
| プレミアムホール | 20 |

一般ホールの料金は1席1,500円、プレミアムホールは1席2,200円です。金額は各上映回の `price` に保存されています。座席は1から各ホールの座席数までの整数です。

# 課題

## 課題1 コードを読み、コメントを書く

`main.py` から処理を追い、Pythonファイルのクラス・関数・メソッドの直前に、通常の `#` コメントを日本語で書いてください。`__init__` とテスト関数も対象です。

クラスでは、役割と保持するデータを説明します。関数・メソッドでは、受け取る値、行う処理、返す値、オブジェクトやファイルを変更するかを説明してください。引数や戻り値がない場合も、そのことが分かるようにします。

コードに書かれている現在の動作を確認して説明します。仕様と実装の違いを見つけたら、調査記録に残してください。修正後はコメントも実際の動作に合わせて更新します。

## 課題2 操作して不具合を調査する

メニューから映画・上映回・予約を確認し、空席確認、新規予約、キャンセルを試します。プログラムを終了して起動し直す確認も行ってください。

仕様と異なる動作を見つけたら、`bug_report.md` に1件ずつ記録します。

- 調査前のデータや事前条件
- 入力した値と操作の順序
- 期待する結果
- 実際の結果

ほかの人が同じ操作で再現できるよう、上映回ID・予約ID・座席番号などを具体的に記録します。原因は、この段階で分からなくても構いません。

## 課題3 不具合を修正する

不具合ごとに、次の順序で進めてください。

1. 自分の `bug_report.md` から修正する不具合を1件選びます。
2. **AIを使わずに、自分で**その不具合を再現するテストを書きます。
3. テストを実行し、その不具合によって失敗することを確認します。構文エラーや準備不足による失敗は再現テストになりません。
4. AIに相談して原因を理解し、AIと一緒に実装を修正します。依頼文は自分で考えてください。
5. すべてのテストを実行し、メニューでも同じ操作を繰り返して修正を確認します。保存に関係する場合は再起動後も確認します。
6. `bug_report.md` に原因、変更したファイルと処理、実行したテストと結果、メニューでの確認結果を書きます。

既存のテストを削除したり、成功させるために期待値を変更したりしないでください。修正はプログラムに行います。データの書き換えだけで不具合を隠さないでください。

## 課題4 上映回ごとの集計を追加する

不具合の修正後、`Cinema` に `build_screening_summary(screening_id: str) -> str` を追加します。メニューに `7. 上映回の集計` を追加し、上映回IDを入力すると集計を表示するようにしてください。

表示する内容は、上映回ID、映画タイトル、上映日時、ホール名、総座席数、有効な予約数、空席数です。

表示形式の例（80席の上映回に有効な予約が3件ある場合）:

```text
上映回: S001
映画: ザ・スーパーマリオギャラクシー・ムービー
上映日時: 2026-11-14 10:00
ホール: 第1ホール
座席数: 80
予約済み: 3
空席: 77
```

- 指定した上映回の `active` の予約だけを数えます。
- 座席数は上映回が使うホールから取得します。
- 予約0件の場合も、すべての項目を表示します。
- 戻り値は改行で区切った文字列です。末尾の改行は付けず、メソッド内では `print()` しません。
- 不明な上映回では既存と同じ例外を発生させます。
- 集計によって予約・状態・JSONを変更しません。
- 別の上映回、キャンセル済み、予約0件、満席、ホールごとの座席数もテストしてください。
